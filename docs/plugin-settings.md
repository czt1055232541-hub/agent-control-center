# 功能插件设置（v0.15.0）

ACC 的框架拥有插件发现、设置、认证和页面挂载；业务页面由功能插件注册。侧边栏从当前运行的插件清单生成，不维护另一份功能目录。框架头部只显示框架连接和插件数量，模型等业务状态归业务页面。

## 设置入口与生效方式

侧边栏的「设置 · 功能插件」是框架固定入口。即使所有功能关闭，设置仍可进入。页面展示所有已安装插件，包括已停用插件；框架不可关闭。

勾选功能后保存。保存仅写入下次启动配置，不动态卸载正在运行的路由、任务或外部进程。页面分别显示当前运行、已保存配置、下次启动状态。确认没有 ACC 操作正在执行后，在项目目录运行：

```text
python scripts/stack.py stop-control-center
python scripts/stack.py serve-control-center --no-build --open
```

仅 ACC 需要重启，DSH 与外部应用无需重启。禁用插件不卸载包、不删除数据；重新启用后原配置和数据保留。

## 功能插件与外部应用

「本地工具」显示名称调整为「外部应用」，插件 ID `acc.local-tools`、API 和原有注册数据保持不变。该插件只管理独立程序的进程、健康检查和页面链接，不承担 ACC 功能插件的启停配置。

- ACC 功能插件：通过 Python entry point / 内建描述注册 API、生命周期、页面卡片；统一在设置管理。
- 外部应用：独立运行的程序，由「外部应用」插件启动、停止或打开；关闭此插件不会停止已运行程序。
- 后续项目优先按插件 SDK 接入；仅需要管理现成独立服务时使用外部应用注册。

## 配置、鉴权和回退

设置文件为主配置目录内的 `plugin-settings.local.json`，默认位于 `config/`；`STACK_SETTINGS_PATH` 改变主配置位置时跟随该目录。内容为版本 1 的 `disabled` 插件 ID 列表。写入前校验未知 ID、框架禁用和依赖缺失；整次请求失败则不保存。

接口：`GET /api/plugins/settings` 查看；`PUT /api/plugins/settings` 保存 `{ "disabled": [...] }`，必须携带有效 `X-Control-Token`。普通 `/api/plugins` 仍仅返回当前运行的插件，不把待生效设置伪装成已生效。

存在 `ACC_DISABLED_PLUGINS` 环境变量时（含空值）优先使用环境变量，设置页只读。要恢复页面管理，移除该变量并重启 ACC。

写入使用同目录临时文件原子替换；存在旧文件时保留一份 `.json.bak`。回退可在设置中重新启用；如果错误配置导致无法启动，停止 ACC 后将备份恢复至原文件再启动。首次保存前无历史文件，因此没有备份；默认全启用可用 `{ "version": 1, "disabled": [] }` 恢复。源代码回退到 v0.14.0 不会读取该新设置文件，可能重新启用所有插件，回退前应据此检查环境变量。

## 验证范围

自动化覆盖未授权不写入、依赖校验、环境变量覆盖、原子替换失败保留旧文件、备份、全部功能禁用时设置可达，以及两个独立宿主进程之间的保存/重新启用。前端渲染测试覆盖框架锁定、禁用保存和空清单设置入口；真实浏览器视觉与点击仍需验收，不能以服务端渲染测试替代。
